# AgentShield v1.0.0 MVP

AgentShield demonstrates why a tool-using AI agent must not authorize its own
side effects. The release puts a deterministic gateway between the model and
four simulated tools, blocks unsafe actions, explains risk with stable reason
codes, and records correlated evidence for investigation.

## Release highlights

- Deny-by-default tool permissions and strict argument schemas.
- Prompt-injection, sensitive-data, SSRF, refund-limit, and rate-limit controls.
- Dashboard, playground, event and tool-call investigation, editable policies,
  and a six-scenario Red Team Lab.
- PostgreSQL/Alembic audit persistence, Docker Compose health orchestration, and
  an offline deterministic demo provider.
- Backend/frontend/integration/security tests plus blocking CI security scans.
- STRIDE threat model, API/security/setup guides, limitations, screenshots, and
  five- and ten-minute interview scripts.

## Verification

```bash
backend/.venv/bin/ruff check backend tests scripts
backend/.venv/bin/pytest backend/tests
npm --prefix frontend test
npm --prefix frontend run lint
npm --prefix frontend run build
docker compose config --quiet
backend/.venv/bin/python scripts/run_attack_demos.py
```

The PostgreSQL and full-stack tests are opt-in because they require a running
database/Compose engine. On a release host, also run:

```bash
RUN_POSTGRES_TESTS=1 backend/.venv/bin/pytest backend/tests/test_postgres_integration.py
docker compose up --build --wait
RUN_INTEGRATION=1 python3 -m unittest tests.integration.test_stack
```

## Upgrade notes

This is the first stable release. Copy the example environment file, keep the
rules provider for a deterministic demo, and do not reuse local credentials in
another environment. Review the documented limitations before adding any real
side-effecting connector.
