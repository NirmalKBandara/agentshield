# Database and migrations

AgentShield uses PostgreSQL, SQLAlchemy 2's async API, and Alembic. The initial
migration creates `users`, `agents`, `tools`, `agent_permissions`, `tool_calls`,
`security_events`, and `policies`, including foreign keys and lookup indexes.

## Apply or inspect the schema

From the repository root, with `backend/.env` configured:

```bash
backend/.venv/bin/alembic -c backend/alembic.ini upgrade head
backend/.venv/bin/alembic -c backend/alembic.ini current
backend/.venv/bin/alembic -c backend/alembic.ini history
```

Compose applies pending migrations before the API starts. To create a future
migration after changing models:

```bash
backend/.venv/bin/alembic -c backend/alembic.ini revision --autogenerate -m "describe change"
```

Review autogenerated migrations before applying them. Migration downgrades can
destroy data, so back up persistent databases first.

## Connection configuration

The backend reads one async SQLAlchemy URL from `DATABASE_URL`:

```text
postgresql+asyncpg://USER:PASSWORD@HOST:5432/DATABASE
```

The readiness endpoint performs `SELECT 1`. Fast unit tests exercise the model
graph with SQLite. CI additionally starts PostgreSQL 17, applies the Alembic
migration to a fresh database, and runs an opt-in test that inserts and reads a
linked user/agent record through the async application session.
